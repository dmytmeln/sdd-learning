# Mission: OpenSpec Deep-Dive Masterclass

## Why

Master **OpenSpec** — the leading lightweight, change-centric Spec-Driven Development (SDD) framework — down to its fundamental principles, directory architecture, command lifecycle, exploratory techniques, and delta spec engineering.

## Context

- **Domain**: Backend services / APIs (Java 17, Spring Boot 3.4.4, PostgreSQL, pgvector, LangChain4j)
- **Practice Ground**: `D:\Personal-Library`
- **Objective**: Transition from simple surface-level awareness to advanced engineering competence with OpenSpec.

## Curriculum Modules

| Module | Focus Area | Key Deliverables |
|---|---|---|
| **Module 1** | **Foundations & Architecture** | Living specs vs Change deltas, Directory layout, Context budgeting, Slash vs CLI command taxonomy |
| **Module 2** | **The Exploratory Phase (`/opsx:explore`)** | Thinking-partner loop, codebase probing, discovering domain invariants, architectural trade-off analysis |
| **Module 3** | **Spec Engineering & Delta Specs** | Grammar of delta specs (`## ADDED`, `## MODIFIED`, `## REMOVED`), BDD Given/When/Then, `proposal.md`, `design.md`, `tasks.md` |
| **Module 4** | **Execution, Sync, & Validation** | `/opsx:apply`, task checklist execution, `openspec validate`, merging to living specs (`/opsx:archive`), drift mitigation |
| **Module 5** | **Advanced Workflows, Pros & Cons** | Multi-change branches, brownfield legacy onboarding, team collaboration, limits & trade-offs |

## Success Criteria

1. Deep architectural comprehension of OpenSpec's state model and directory conventions.
2. Fluency across all OpenSpec CLI and AI Slash commands.
3. Ability to formulate high-precision exploratory queries (`/opsx:explore`) that uncover hidden domain traps.
4. Mastery of delta specification authoring with strict BDD acceptance criteria.
5. End-to-end execution of a complete feature lifecycle on `Personal-Library` without context drift or prompt degeneration.
